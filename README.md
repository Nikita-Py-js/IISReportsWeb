# IIS Reports 3.0.2

**Анализ журналов IIS, диагностика HTTP-ошибок и мониторинг сайтов.** Отдельный проект для установки с нуля: IIS + ASP.NET Web Site (.NET Framework 4.8) + Microsoft SQL Server + Windows-служба.

[Чистая установка](docs/INSTALL.md) · [Требования](docs/PREREQUISITES.md) · [Настройки](docs/CONFIGURATION.md) · [HTTPS / CSRF](docs/SECURITY.md) · [Обновление](docs/UPGRADING.md) · [Устранение ошибок](docs/TROUBLESHOOTING.md)

> **Одного базового IIS недостаточно.** Нужны компоненты ASP.NET 4.x и Windows Authentication, .NET Framework 4.8/4.8.1, а также доступный экземпляр SQL Server. SQL можно установить рядом или использовать отдельный сервер. Старая версия IIS Reports и её `Web.config` не требуются.

> **Состав поставки:** исходники, SQL, PowerShell-скрипты и документация. В исходном ZIP нет предварительно собранного EXE. `tools/Build-And-Test.ps1` собирает его на Windows без Visual Studio и NuGet. Дистрибутивы Microsoft, сертификаты и настоящие GeoIP/ASN-базы не включены.

## Возможности

| Область | Что доступно |
|---|---|
| Журналы | W3C, несколько источников, фильтры, детализация, CSV, переходы из сводок к запросам |
| Ошибки | 404/5xx по адресам, подстатусы, Win32-коды, Referer и исходные строки |
| Производительность | Временные графики, RPS/RPM, среднее время, p95, сравнение периодов |
| Импорт | Независимая Windows-служба, контрольные точки, версии файлов, Verify, Replay, карантин |
| Мониторинг | HTTP-проверки сайтов, проверка текста/JSON, правила, инциденты, очередь JSON-webhook |
| Доступ | Windows Authentication, роли читателя и оператора, CSRF, аудит операций |
| Обогащение | Локальные IPv4 GeoIP/ASN CSV, эвристическая классификация клиентов |

Windows-служба работает независимо от открытого браузера. Веб-интерфейс ставит задания в SQL, а не выполняет длительный импорт внутри HTTP-запроса.

## Архитектура

```text
Браузер ──HTTPS / Windows Authentication──> IIS / ASP.NET
                                               │
                                      отчёты и задания
                                               │
                                        SQL Server: ir3
                                               ▲
                                       импорт / результаты
                                               │
                                       IISReportsAgentV3
                                        ├── W3C .log
                                        ├── HTTP-проверки
                                        └── JSON-webhook
```

Одна база — один активный сборщик. Для независимых серверов используйте отдельные базы. Общий кластер нескольких агентов в этом выпуске не реализован.

## Начало работы

1. Распакуйте комплект **вне web-каталога**, например в `C:\Deploy\IISReports-3.0.2`.
2. Откройте **Windows PowerShell 5.1 x64 от администратора**.
3. Выполните проверку компонентов и сборку:

```powershell
$pkg = 'C:\Deploy\IISReports-3.0.2'
& "$pkg\tools\Install-Prerequisites.ps1" -InstallMissing
& "$pkg\tools\Build-And-Test.ps1"
```

Если скрипт сообщает о необходимой перезагрузке или отсутствующем .NET Framework, сначала устраните это условие. Он не перезагружает сервер автоматически.

4. Продолжайте по [пошаговой чистой установке](docs/INSTALL.md): SQL → конфигурации → сайт → служба → права → источники → проверки → запуск.

**Не копируйте весь проект в `wwwroot`.** В IIS публикуется только содержимое `web/`; установщик `Install-Web.ps1` делает это сам.

## Какие имена не следует путать

| Параметр | Пример | Назначение |
|---|---|---|
| Имя IIS-сайта | `IISReportsV3` | Объект в диспетчере IIS, не DNS |
| Имя пула | `IISReportsV3` | Процесс сайта и его SQL/NTFS-права |
| Физический путь | `C:\inetpub\wwwroot\IISReportsV3` | Содержимое `web/` |
| Публичный URL | `https://reports.example.test:8443/` | Адрес браузера |
| PublicOrigin | `https://reports.example.test:8443` | Точный протокол + хост + порт для CSRF |
| SiteId источника | `2` | ID **анализируемого** сайта, соответствующий `W3SVC2` |
| Имя службы | `IISReportsAgentV3` | Фоновый сборщик |

Названия и домены в документации — примеры. Проект не содержит настроек конкретного прежнего сервера.

## Структура репозитория

```text
agent/                  исходники и .csproj Windows-службы
  source/               автономный комплект исходников EXE
web/                    только файлы веб-приложения
  App_Code/             C# 5, компилируемый ASP.NET
  App_Data/             примеры формата GeoIP/ASN
sql/                    схема ir3, разрешения и проверки
tools/                  установка, сборка, тестирование и упаковка
tests/                  локальные C#, SQL- и браузерные тесты
docs/                   документация Markdown
.github/                пример Windows CI и шаблоны issue
build/                  сюда попадает результат Windows-сборки
```

Общие исходники агента находятся в `web/App_Code/V3Core.cs`, `V3Import.cs`, `V3Monitoring.cs`. В `agent/source/` приложены идентичные копии для самостоятельной сборки. [Карта исходников EXE](agent/SOURCE-MAP.md).

## Что включено из исправлений

**Установка:** создание отсутствующих папок; отказ от перезаписи конфигов; проверка настоящего имени IIS-сайта; включённый `Default Document`; отдельный web-каталог; инициализация без старого `ConnStr`; явная регистрация реальных источников вместо W3SVC1–3 на каждом сервере.

**SQL и импорт:** отдельные DDL-пакеты внутри транзакции, исправленные SQL-литералы состояний, точные параметры `datetime2(7)`, сохранение истории и байтовых контрольных точек.

**Безопасность:** точный публичный Origin; строгая проверка токена; изолированные HTTP-запросы теста без переноса заголовков; резервные копии конфигов вне сайта; упаковка только файлов из манифеста.

Подробнее: [CHANGELOG](CHANGELOG.md).

## Сборка ZIP с исполняемым файлом

```powershell
& "$pkg\tools\Build-And-Test.ps1"
& "$pkg\tools\Make-Windows-Release.ps1" -SkipBuild
```

В `release/` появится Windows-пакет с `build/IISReports.Agent.exe`, исходниками и хешами. При `-SkipBuild` проверяется, что исходники не изменились после сборки. Рабочие конфиги, пароли, базы и журналы в пакет не собираются. Собственные секреты всё равно не следует записывать в исходники или шаблоны.

## Проверки и ограничения

Проверки поставки описаны в [TESTING](docs/TESTING.md), результат доступных проверок — в `tests/release-validation.json`. Статическая/браузерная проверка не заменяет испытание Windows Authentication, SQL и службы на целевом сервере.

Это консолидированная версия исходников, **не заявление о сертифицированной готовности к production**. Перед рабочим внедрением выполните Windows-сборку, HTTP/CSRF-тест, SQL-проверки и тест восстановления из резервной копии.

Не реализованы: HTTPERR/FREB, OpenTelemetry, IPv6-обогащение, автоматическое обновление GeoIP-баз, SMTP/Telegram-адаптеры, автоматическая очистка истории и активная работа нескольких агентов с одной базой. Webhook — обычный JSON с возможными повторными доставками. Проверки доступности не отправляют Windows-учётные данные.
