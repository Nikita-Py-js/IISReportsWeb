# Проверки поставки

[← README](../README.md)

## Что проверено при подготовке 3.0.2

В этой среде выполнены браузерные сценарии Chromium с подставным API, проверка структуры/ссылок документации, XML, синтаксиса JavaScript, согласованности копий исходников, SQL-порядка и состава архивов. Конкретные результаты находятся в [release-validation.json](../tests/release-validation.json) и [browser-results.json](../tests/browser-results.json).

**Здесь нет Windows/IIS/SQL Server.** Новые установочные PowerShell-скрипты не исполнялись на Windows; компиляция .NET Framework, NTLM/Kerberos, живой SQL и Windows-служба не проверены этим прогоном. Прохождение пользователем 21 локального теста предыдущей сборки не считается автоматически результатом новой версии.

## Обязательная проверка на целевом Windows

```powershell
& "$pkg\tools\Test-PowerShellSyntax.ps1"
& "$pkg\tools\Build-And-Test.ps1"
& "$pkg\tools\Initialize-Database.ps1" @dbArgs -VerifyOnly
& "$pkg\tools\Test-Http.ps1" -ApplicationUrl $publicUrl
```

Последний скрипт обязан отклонить все некорректные запросы, включая отсутствие CSRF-заголовка. Он не следует редиректам и не отключает проверку TLS-сертификата.

Положительный `-QueueScan` создаёт задание — используйте его осознанно.

## SQL-интеграция

`Test-Sql.ps1` запускает включённый `SqlIntegrationTests.exe`. Это **не read-only тест**: создаются тестовые источники/данные, выполняются импорт, replay, проверки инцидентов/очереди и тестовые манипуляции. Запускайте только на отдельной disposable test-базе со схемой ir3, не на рабочих данных и не параллельно агенту.

Тест должен получать строку подключения выделенной тестовой базы через отдельный конфиг; не передавайте ему production agent-config.

## Браузерный smoke

Не обязателен для эксплуатации. На машине разработчика с Python, Playwright и Chromium:

```text
python tests/browser_smoke.py --chromium <path-to-chromium>
```

API подменяется фикстурами. Проверяются UI, экранирование, фильтры, отправка CSRF-заголовка, повтор после истечения токена и отказ от повтора при неверном Origin. Это не проверка реального серверного CSRF.

## CI

`.github/workflows/windows-build.yml` — пример workflow для нового репозитория. Он выполняет PowerShell parsing, C#-сборку и локальные unit-тесты, затем собирает Windows ZIP. SQL и живой IIS в этом workflow не поднимаются.

Результаты workflow нельзя считать полученными, пока вы не запустили его в своём репозитории. В исходном ZIP отсутствуют предварительно собранные EXE и выдуманные CI-badges.

## Проверка архива

`SHA256SUMS.txt` содержит хеши файлов, кроме самого списка. Хеш не является цифровой подписью автора. Проверяйте происхождение канала поставки.

`Make-Windows-Release.ps1` сверяет исходники с BUILDINFO.json и упаковывает только SOURCE-MANIFEST.txt и известные build-артефакты. Если после сборки код менялся — пересоберите.
