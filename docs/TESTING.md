# Проверки версии 3.1.1

[← README](../README.md)

Ни одна локальная статическая проверка не доказывает успешную установку на Windows.

## Выполняется в этой среде

- Браузер Chromium/Playwright с подставным JSON API: отображение, навигация, чекбоксы, конфликты ревизий, экранирование данных.
- Проверки согласованности исходников, SQL-файлов, версии, копий standalone-agent и относительных Markdown-ссылок.
- Дополнительные проверки контракта установщика: шаги, параметры вызываемых скриптов, защита Config, side-effect-free csrf-check, обязательные проверки файлов/сборки.
- Синтаксис JavaScript через Node.js; целостность ZIP и манифестов.

Результаты включены в `tests/*-results.json` и итоговый `tests/RELEASE-VALIDATION.json`. Это отчёт реально запущенных здесь проверок, а не результаты Windows.

## Обязательно на Windows

```powershell
.\tools\Test-PowerShellSyntax.ps1
.\tools\Test-SqlConnectionBuilder.ps1
.\tools\Test-SetupPaths.ps1
.\tools\Test-InstallWorkflow.ps1
.\tools\Build-And-Test.ps1
```

`Test-InstallWorkflow.ps1` использует собственный временный каталог и проверяет в том числе создание обоих конфигов, повторное использование, конфликт SQL-настроек и завершение неполной пары. Он не устанавливает IIS, не создаёт службу и не подключается к SQL.

`Build-And-Test.ps1` проверяет C# 5, локальные unit-тесты и создаёт BUILDINFO только после успеха.

## Реальное окружение

```powershell
.\tools\Test-SqlConnection.ps1 -SqlServer 'localhost' -Database 'master'
.\tools\Initialize-Database.ps1 -SqlServer 'localhost' -Database 'IISReports' -VerifyOnly
.\tools\Test-Http.ps1 -ApplicationUrl 'https://reports.example.test:8443/'
.\tools\Test-Health.ps1 -ApplicationUrl 'https://reports.example.test:8443/'
```

Подставьте свой SQL и адрес. SQL-сертификат/права не обходятся автоматически.

HTTP-тест должен пройти отрицательные проверки Origin, заголовка, токена и cookie, плюс корректный POST к csrf-check без побочных действий.

## Приёмка автоматического импорта

1. Включить источник и убедиться, что появились записи.
2. Повторить проход без новых строк — число событий не должно увеличиться от повторного чтения.
3. Снять чекбокс и сохранить. Новые порции не должны фиксироваться; выполняющаяся транзакция может завершиться перед паузой.
4. Дописать тестовый журнал, включить источник и проверить дочитывание.
5. Перезапустить агент и убедиться в сохранении выбора.
6. Добавить IIS-сайт: после discovery должен появиться новый источник.
7. Проверить карантин некорректных строк и ожидание незавершённой строки.
8. Убедиться, что у службы нет записи в программу SYSTEM-discovery.

Генератор тестовых логов и SQL-интеграционные EXE используйте **только на отдельной одноразовой тестовой базе**, не на базе мониторинга. Прочитайте заголовки `Test-Sql.ps1`, `Test-DiscoverySql.ps1` и соответствующих C#-тестов перед запуском.

## Что здесь НЕ выполнено

Нет установленного Windows/.NET Framework/IIS/SQL Server. Не выполнены C#-компиляция, PowerShell 5.1, NTFS ACL, установка службы, Kerberos/NTLM, реальные SQL-запросы/миграции, настоящие webhook и импорт Windows-журналов. EXE из этой среды не поставляется.

GitHub Actions — только конфигурация будущего Windows-прогона, а не выполненная проверка. Публикации репозитория или успешного CI в этой поставке нет.
