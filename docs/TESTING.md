# Проверки IIS Reports 3.1.0

[← README](../README.md)

## Что проверялось при подготовке исходников

- Браузер Chromium с **подставным API**: существующие сценарии аналитики и новые сценарии флажков, сохранения, конфликтов и ошибок. Результат: `tests/browser-results.json`.
- Статическая согласованность версии, копий C# для агента, XML, SQL-порядка, защитных проверок, относительных ссылок Markdown: `tests/consistency-results.json`.
- Синтаксис JavaScript через `node --check`.
- Целостность ZIP, совпадение файлов и SHA256.

**Это не проверка реального SQL, IIS или NTLM/Kerberos.** В среде подготовки нет Windows/.NET Framework. Сборка C#, выполнение PowerShell на Windows, запуск задачи SYSTEM, чтение конфигурации реального IIS, ACL и интеграция MSSQL здесь не выполнялись.

## 1. Проверка на Windows

Из проверенного пакета, в Windows PowerShell 5.1 x64:

```powershell
.\tools\Verify-Package.ps1
.\tools\Test-SqlConnectionBuilder.ps1
.\tools\Build-And-Test.ps1
```

`Build-And-Test.ps1` проверяет синтаксис PS, идентичность канонических и автономных исходников, компилирует сайт, HTTP-обработчик и агент с C# 5, затем выполняет `UnitTests.exe`.

Unit-тесты покрывают W3C, байтовые смещения, незавершённые строки, UTF-8, SQL datetime2, Origin, валидацию снимка IIS и выбора источников. Наличие файлов тестов не означает, что они были выполнены на вашем сервере.

## 2. SQL-интеграция — только отдельные тестовые базы

Для каждой проверки используйте отдельную новую БД, применив 001 и 005. В конфиге `ConnStr` должен указывать **на неё**, не на рабочую.

Импорт и пауза:

```powershell
.\tools\Test-Sql.ps1 -AgentConfig 'C:\Deploy\TestConfigs\import-test.config'
```

Проверяются повторный импорт, повреждения, продолжение строк, пауза/возобновление, конфликт Revision. Тестовые записи сохраняются для исследования; не запускайте этот сценарий вместо проверки рабочей БД.

Автообнаружение:

```powershell
.\tools\Test-DiscoverySql.ps1 `
    -AgentConfig 'C:\Deploy\TestConfigs\discovery-empty.config' `
    -EmptyTestDatabase
```

Этот тест **отказывается работать с непустой `ir3.Sources`/`ir3.Requests`** и при действующей блокировке агента. Проверяет:
- первый сайт включён;
- обнаружение не сбрасывает паузу и не создаёт дубли;
- перенос каталога наследует выбор;
- исчезнувшие источники сохраняются;
- ожидающий каталог не импортируется до готовности;
- конфликт в массовом изменении откатывает всю транзакцию.

После теста фикстуры остаются отключёнными. `Test-Sql.ps1` и `Test-DiscoverySql.ps1` не используйте последовательно на одной БД: второй требует пустую.

## 3. HTTP / CSRF

```powershell
.\tools\Test-Http.ps1 -ApplicationUrl 'https://reports.example.test:8443/'
```

Каждый HTTP-запрос создаётся независимо, общими остаются только явно передаваемые cookie. Нет переиспользования заголовков `WebRequestSession`.

Проверяются Windows identity, выдача токена, запрет GET-изменения, неверный Origin, отсутствующий и неверный CSRF-заголовок, отсутствующая cookie. Для `sources-save` также проверяется отказ без токена и валидация пустого набора с корректным токеном (400, без изменений).

Нормальный отрицательный тест не ставит задания и не меняет выбор источников. При неисправной защите тесты `refresh` могут создать Scan-задание: это фиксируется как отказ. Положительный `-QueueScan` намеренно создаёт одно задание; используйте отдельно.

## 4. Приёмка обнаружения и интерфейса

На отдельном стенде:
1. Установите агент/задачу, запустите их. Сверьте список с IIS Manager.
2. Снимите флажок одного сайта и сохраните. Проверьте БД `Enabled=0`, затем перезапустите агент и задачу — выбор сохраняется.
3. Создайте запросы к отключённому сайту. Его контрольная точка не должна продвигаться после завершения уже выполнявшейся порции.
4. Включите источник: накопленные доступные строки дочитываются, история не обнуляется.
5. Создайте новый сайт с W3C-логированием. До создания каталога — ожидание, после появления файлов — импорт без ручной регистрации.
6. Удалите тестовый сайт из IIS: история остаётся, источник отмечается `not_in_iis`.
7. Откройте две вкладки. Конфликтующие сохранения одного источника должны давать 409, а не молча перетирать выбор.
8. Отключите задачу на время больше TTL: появляется ошибка обнаружения, ранее известные источники не удаляются.
9. Проверьте отсутствие записи у агента в каталог publisher; пользователи IIS Reports не должны иметь права менять этот скрипт.

На рабочем сервере не обрезайте и не подменяйте журналы ради теста.

## 5. Браузерный тест разработчика

Python и Playwright нужны только разработчику, не установленному приложению:

```bash
python tests/browser_smoke.py --chromium /path/to/chromium
python tests/validate_release.py
node --check web/v3.js
```

Скриншот в README получен с фиктивными данными. Он иллюстрирует интерфейс, не подтверждает работу с реальной БД.
