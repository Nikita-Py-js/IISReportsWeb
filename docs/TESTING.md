# Проверки выпуска Simple 3.2.0

[← README](../README.md)

## Выполнено при подготовке

- 44 сценария Chromium **с подставным JSON API**: открытие вкладок, новый POST-клиент без токена, чекбоксы, пауза/возобновление, несохранённый выбор, конфликт редакций, экранирование HTML, ручная проверка, редактор правил.
- `node --check` для JavaScript.
- Проверки структуры приложения, XML, ссылок Markdown, схемы и полного ZIP — результат в `tests/validation.json`.

Это не проверка реального SQL или Windows Authentication. Снимок `tests/sources.png` сделан на тестовых данных.

## Не выполнено в среде подготовки

Windows PowerShell 5.1, компиляция C# под .NET Framework, NTFS ACL, создание сайта IIS и SQL-команды на реальном SQL Server. Их выполнение необходимо подтвердить на целевой Windows-машине.

## Необязательная проверка компиляции

Для установки ручная сборка не нужна: IIS компилирует исходники сам. Разработчик может до установки запустить:

```powershell
& 'C:\Deploy\IISReports-Simple-3.2.0\tests\Test-Compile.ps1'
```

Скрипт компилирует **все App_Code, обработчик и тесты** с `/langversion:5` во временный каталог и выполняет тесты парсера. Проверяется наличие EXE перед запуском. К рабочему сайту и SQL он не обращается.

## Приёмка после установки

Откройте страницу и нажмите «Обновить / импортировать». Проверьте:
- источники появились без снимка ProgramData и задачи Windows;
- два последовательных обновления неизменных файлов не увеличивают число записей;
- после снятия флажка импорт выбранного источника приостанавливается, уже импортированная история не исчезает;
- после возвращения флажка и появления новой полной строки число записей растёт;
- перезапуск пула не сбрасывает позиции; после открытия браузера импорт возобновляется;
- после закрытия браузера новые проходы импорта не запускаются; уже выполнявшаяся порция может завершиться. После открытия доступный хвост дочитывается.

GET `refresh` должен возвращать 405, POST без `X-IISReports-Request` — 403. Это минимальная защита способа вызова, не авторизация: любой пользователь, допущенный IIS, может послать корректный POST.

Сначала проверяйте на копии базы/логов. Изменение/обрезание уже обработанных файлов должно давать ошибку сохранения целостности, а не удалять историю. Изменённый файл требует отдельной контролируемой процедуры восстановления.
