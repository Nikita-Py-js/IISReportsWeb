# Автоматический мониторинг всех сайтов IIS

[← README](../README.md) · [Чистая установка](INSTALL.md) · [Обновление](UPGRADING.md)

## Что означает «все логи»

Обнаруживаются **локальные сайты, зарегистрированные в IIS**, и их каталоги файловых журналов **W3C**. У каждого сайта используется его фактическая настройка Logging, включая нестандартный диск или базовый каталог; каталог сайта определяется как `<Logging.Directory>\W3SVC<ID>`.

Агент импортирует существующие и вновь появляющиеся `.log` внутри включённых источников. Это не сканирование всего диска: системные события Windows, FTP, HTTPERR, FREB, NCSA, бинарные логи, `.gz`, ETW-only и централизованные журналы этим модулем не импортируются. Для неподдерживаемой настройки сайт виден с объяснением, а не исчезает молча.

## Как это работает

```text
Конфигурация IIS (только чтение)
          |
          v
Задача IISReports-DiscoverSites — SYSTEM, раз в минуту
          |  Список сайтов + право чтения только каталогов W3C
          v
%ProgramData%\IISReports\Discovery\sites.json
          |  Агент может читать, но не изменять
          v
IISReportsAgentV3 — отдельная виртуальная служебная учётная запись
          |  Сверка списка; сохранённые Enabled не перезаписываются
          v
MSSQL ir3.Sources ----> импорт только Enabled=1 и доступных источников
          ^
          |  Windows Authentication + роль редактора + CSRF
          |
Вкладка «Источники»: флажки + «Сохранить выбор»
```

Задача нужна, чтобы **не выдавать агенту или веб-пулу права администратора и чтение всей конфигурации IIS**. В снимке нет SQL-пароля, сертификатов или паролей пулов. SYSTEM выполняет только защищённый локальный скрипт, без SQL-доступа. Защитите права администраторов, которые могут менять саму конфигурацию IIS.

## Правила включения и отключения

| Действие | Результат |
|---|---|
| Первый запуск на новом сервере | Все обнаруженные источники включены по умолчанию. |
| Обновление с 3.0.2 | Существующие `Enabled` сохраняются. Автообнаружение не включает обратно ранее отключённый источник. |
| Снять флажок и сохранить | Агент прекращает новые порции импорта; история и смещения остаются. |
| Снять флажок без сохранения | Только несохранённый выбор в текущем браузере. |
| Включить обратно | Продолжение с контрольной точки; доступные строки, накопившиеся за паузу, импортируются. |
| Перезапустить агент / IIS | Выбор остаётся в MSSQL. |
| Добавить новый сайт в IIS | Включается автоматически после очередного снимка и прохода агента. |
| Изменить путь Logging у сайта | Создаётся отдельный источник для нового пути с предыдущим выбором того же SiteId; старый источник архивно остаётся в списке. |
| Удалить сайт из IIS | Источник получает `not_in_iis`, дальнейший автоимпорт прекращается; данные не удаляются. |
| Отключить все видимые | Действует на текущий отфильтрованный список, не на будущие сайты. |

Обычно изменение импортируемого списка применяется на следующем проходе агента (по умолчанию 30 секунд). Обнаружение нового сайта — ближайшая минута плюс очередной проход. Это интервалы планирования, не SLA: первая загрузка больших архивов может занять дольше.

### Граница остановки

Перед каждым файлом и перед транзакцией сохранения порции агент проверяет `Enabled`. Сохранение порции и изменение флажка используют блокировку строки источника. Если порция уже фиксируется, сохранение флажка может дождаться её завершения; после успешного ответа на паузу новые порции этого источника не фиксируются до включения.

Отключение не очищает SQL, не меняет `CurrentRequests`, не убирает историю из отчётов, не отключает активные проверки URL или правила алертов и не отзывает NTFS-права службы. Для ограничения просмотра истории используются отдельные права доступа, а не этот флажок.

### Права и параллельное редактирование

Редактору разрешено менять **только `Enabled` и `Revision`** в `ir3.Sources` через этот API. Браузер не задаёт пути к файлам и не запускает PowerShell.

`POST sources-save` проверяет Windows-роль, CSRF и номер ревизии. Все изменения одного запроса применяются транзакционно. Если другой оператор уже поменял выбор, сервер возвращает `409 revision_conflict`, не сохраняя часть списка. Интерфейс перечитывает серверное состояние и предлагает повторить выбор.

`Replay` и `New version` отключённых или недоступных источников запрещены также на сервере. `Verify` остаётся доступной проверкой существующей истории.

## Источники без логов и нестандартные настройки

- `waiting_directory`: IIS ещё не создал каталог. Флажок сохранён; импорт начнётся, когда каталог появится.
- `logging_disabled`: Logging выключен в IIS. Старые W3C-файлы можно читать, новых записей не будет.
- `path_or_acl_error`: недоступный путь, UNC, reparse point либо ошибка выдачи NTFS-прав.
- `format_unsupported`: выбран не W3C.
- `central_unsupported`: включён общий журнал на сервер, а не отдельные журналы сайтов.
- `etw_only`: IIS отправляет события только в ETW, не в файлы.
- `not_in_iis`: сайт удалён или изменил путь. История сохранена.

Импортёр не меняет конфигурацию Logging автоматически. Задайте **Site / W3C / File** в IIS, включите поля `date`, `time`, `cs-method`, `cs-uri-stem`, `sc-status`; для метрик также `time-taken`. Порядок полей определяется по `#Fields`.

Защищённые от наследования ACL отдельных файлов могут по-прежнему запрещать чтение: автоматическая задача добавляет наследуемые Read/Execute на каталог сайта, но не снимает explicit deny и не сбрасывает ACL всех файлов. В этом случае исправьте разрешения целевого журнала вручную.

## Проверка

```powershell
Get-Service IISReportsAgentV3
Get-ScheduledTaskInfo -TaskName 'IISReports-DiscoverSites'
Get-Content "$env:ProgramData\IISReports\Discovery\sites.json" -Raw -Encoding UTF8 |
    ConvertFrom-Json | Select-Object success, machineName, generatedUtc, error
```

После первого прохода:
- `Reports.ashx?action=sources` содержит `sources`, `files`, `discovery`;
- `health` содержит `agentOnline=true` и `discoveryHealthy=true`;
- источники с реальными журналами получают `LastScanUtc`;
- ошибки обнаружения видны над таблицей.

Проверка флажка: снимите один, сохраните, запомните позицию; добавьте запросы к исходному сайту и дождитесь сброса буфера IIS. Для отключённого источника позиция не продвигается. Включите обратно — строки дочитываются без повторения уже импортированных смещений.

Сломанный, устаревший или неполный снимок не считается «все сайты удалены»: сохраняется прежний список и выводится ошибка. Это консервативное поведение; ранее известные доступные источники продолжают импорт.

## Изменение интервала и восстановление задачи

```powershell
Stop-Service IISReportsAgentV3
& "$pkg\tools\Install-AutoDiscovery.ps1" -AgentDirectory $agentRoot -IntervalMinutes 1
Start-Service IISReportsAgentV3
```

Скрипт сохраняет резервную копию конфигурации агента внутри защищённого каталога службы. `-NoGrantLogRead` запрещает автоматическое добавление ACL при переустановке задачи; уже выданные права не отзываются. Тогда чтение журналов настройте самостоятельно.

## Ограничения текущей версии

Одна БД предназначена для одного IIS-сервера/агента. Не объединяйте в ней SiteId разных серверов. Назначение SiteId IIS заново другому сайту не может быть надёжно отличено от изменения конфигурации прежнего сайта — следите за повторным использованием ID.

Снимок отражает сайты IIS, а не произвольные старые папки `W3SVC*`, оставшиеся после их удаления. Ручная регистрация таких архивов остаётся дополнительным режимом через `Register-LogSource.ps1`, но не требуется для всех действующих сайтов.
