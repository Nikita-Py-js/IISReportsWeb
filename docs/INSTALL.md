# Установка IIS Reports Simple

[← README](../README.md)

## 1. Распакуйте проект

Ожидаемая папка: `C:\Deploy\IISReports-Simple-3.2.0`.

Не распаковывайте целый архив в `wwwroot`: Setup сам копирует **только `web`**.

На сервере нужны IIS, .NET Framework 4.8 и SQL Server. Сборка EXE, Visual Studio, Node.js, Python и Планировщик не нужны для установки. Команды выполняются в **Windows PowerShell 5.1 x64 от администратора**. SQL-права текущего аккаунта проверяются фактическим подключением: администратор Windows не обязательно имеет права DBA.

## 2. Если есть старая версия, остановите её импорт

```powershell
& 'C:\Deploy\IISReports-Simple-3.2.0\Stop-Legacy.ps1'
```

Это останавливает/отключает только `IISReportsAgentV3` и `IISReports-DiscoverSites`, если они существуют. Старые файлы, SQL и другие сайты не удаляются. На чистом сервере шаг пропускается. Подробнее: [переход](UPGRADE.md).

## 3. Запустите одну команду

Для SQL на этой машине, экземпляр по умолчанию:

```powershell
& 'C:\Deploy\IISReports-Simple-3.2.0\Setup.ps1' -SqlServer 'localhost' -Database 'IISReports'
```

Для вашего доверенного локального тестового SQL с самоподписанным/недоверенным сертификатом:

```powershell
& 'C:\Deploy\IISReports-Simple-3.2.0\Setup.ps1' -SqlServer 'localhost' -Database 'IISReports' -TrustSqlCertificate
```

Выполняется **один** подходящий вариант, а не оба подряд. У именованного экземпляра имя другое, например `localhost\SQLEXPRESS`; используйте настоящее имя из SSMS. Не меняйте MSSQLSERVER на SQLEXPRESS без проверки.

Результат:
- база IISReports создаётся только при отсутствии; схема ir3 дополняется совместимыми объектами;
- рабочие файлы размещаются в `C:\inetpub\wwwroot\IISReportsSimple`;
- `Web.config` создаётся непосредственно в этой папке — отдельного `$configDir` нет;
- сайт и пул называются `IISReportsSimple`;
- пул получает чтение журналов и DML-права только на ir3;
- адрес — `http://localhost:8090/`, анонимный доступ в IIS, локальная привязка.

Setup не меняет прежние сайт/пул `IISReportsV3` и не занимает их порт 8083. Сертификат и DNS не запрашиваются. Если порт 8090 занят, задайте другой:

```powershell
& 'C:\Deploy\IISReports-Simple-3.2.0\Setup.ps1' -SqlServer 'localhost' -Database 'IISReports' -Port 8091 -TrustSqlCertificate
```

При ошибке остановитесь и исправьте **её**, не запускайте прежние 3.1.x этапы. Новой установки `Agent`, `Permissions`, `SecurityTest` здесь нет.

После частично выполненной установки можно повторить **ту же** команду. Если каталог помечен этим установщиком и параметры совпадают, конфигурации не переписываются, а SQL/ACL-этапы повторяются. Аутентификация уже созданного сайта повторным запуском не сбрасывается. Занятая чужая папка никогда не очищается. Установщик не является автоматическим обновлятором версии.

## 4. Откройте панель

`http://localhost:8090/` или выбранный порт.

Первое обращение компилирует ASP.NET-код. Затем кнопка «Обновить / импортировать» начинает чтение доступных журналов. Большой архив обрабатывается порциями за несколько обновлений.

На вкладке **Источники** снимите флажки ненужных каталогов и нажмите **Сохранить выбор**. Верхний фильтр «Сайт» меняет отображение аналитики, но не выбор источников импорта.

Автоимпорт включён по умолчанию: один проход после окончания предыдущего, примерно каждые 30 секунд, пока вкладка активна. Снятие верхнего флажка выключает автоимпорт, но ручная кнопка остаётся доступна.

## Нестандартные пути журналов

Setup добавляет базовые каталоги W3C-журналов из IIS. Можно добавить корень вручную:

```powershell
& 'C:\Deploy\IISReports-Simple-3.2.0\Setup.ps1' -SqlServer 'localhost' -Database 'IISReports' -LogRoots 'D:\IISLogs','E:\OtherLogs' -TrustSqlCertificate
```

В дальнейшем корни можно изменить в `Web.config`, ключ `LogRoots`, разделитель `;`. Программа ищет непосредственные подпапки `W3SVC123`. Саму папку `...\W3SVC123` тоже можно указать корнем. У пула должны быть права чтения. При новой папке под существующим разрешённым корнем обычное наследование NTFS передаст права; защищённые ACL дочерних папок нужно проверить отдельно.

## Внешний адрес / HTTPS

Сначала проверьте локальный сайт. После этого через IIS Manager добавьте нужную HTTPS-привязку к **IISReportsSimple**. Выбор сертификата и DNS — настройки IIS, не параметры приложения. Старую привязку 8083 нельзя одновременно назначить двум сайтам.

`IISReportsPublicOrigin` добавлять не нужно: здесь нет проверки внешнего домена и выдачи CSRF-токена. Аутентификацию и доступ ограничивайте средствами IIS/прокси/сети. Встроенного пароля у Simple нет.

## Диагностика

```text
/Reports.ashx?action=health
/Reports.ashx?action=diag
```

`diag` показывает корни журналов, последнюю порцию импорта и учётную запись пула. Отсутствие службы агента больше не является ошибкой.

Если сайт не видит логи — проверьте путь и Read/ReadAndExecute для `IIS APPPOOL\IISReportsSimple`. Если SQL сообщает Login failed — SQL-прав нужен именно пулу, не пользователю браузера. Если SQL сообщает недоверенную цепочку сертификата — настройте доверие либо осознанно используйте `-TrustSqlCertificate` на вашем локальном стенде.

SQL-сертификат и HTTPS-сертификат сайта — разные сертификаты.
