# Обновление 3.0.x → 3.1.0

[← README](../README.md) · [Автоматические источники](AUTO-SOURCES.md)

Версия 3.1.0 добавляет автоматическое обнаружение локальных IIS-сайтов и сохранение выбора мониторинга в веб-интерфейсе. Нельзя обновить только HTML: нужны серверные классы, EXE агента, SQL-миграция 005 и защищённая задача обнаружения.

**Старые запросы, исходные строки, поколения файлов и контрольные точки не удаляются.** Существующее `Enabled=0` сохраняется при обнаружении того же источника. Имена, явно заданные в `sites.json`, имеют прежний приоритет.

## 1. Подготовка

Сделайте проверяемую резервную копию БД и файлов сайта/службы. Храните копии с конфигурациями и паролями вне `wwwroot`, с закрытыми ACL. Не оставляйте старые `.cs` внутри `App_Code`.

Распакуйте **новый** пакет отдельно:

```powershell
$ErrorActionPreference = 'Stop'
$pkg = 'C:\Deploy\IISReports-3.1.0'
$webRoot = 'C:\inetpub\wwwroot\IISReportsV3'
$agentRoot = 'C:\Services\IISReportsAgentV3'

# Укажите фактический ПУЛ. Он может не совпадать с именем папки/сайта.
$poolName = 'IISReportsV3'

& "$pkg\tools\Verify-Package.ps1"
& "$pkg\tools\Build-And-Test.ps1"
```

При ошибке компиляции остановитесь: работающая установка ещё не изменена.

## 2. Остановите старый агент и пул

Windows PowerShell 5.1 x64 от администратора:

```powershell
Import-Module WebAdministration
Stop-Service IISReportsAgentV3
Stop-WebAppPool -Name $poolName
Get-Service IISReportsAgentV3
```

Не останавливайте другие пулы. Если служба не установлена, используйте раздел установки агента в [INSTALL.md](INSTALL.md), а не этот сценарий замены EXE.

## 3. Обновите SQL

Выберите **ту же базу**, в которую входят текущие сайт и агент. Под SQL-администратором выполните:

```text
sql\005-auto-sources.sql
sql\006-auto-sources-verify.sql
```

Миграция выполняется транзакционно и повторно применима. Она добавляет метаданные к `ir3.Sources`, таблицу `ir3.DiscoveryState`, индекс и разрешение веб-роли изменять только `Enabled, Revision`. Ожидаемая версия схемы — **310**; таблиц — **19**.

Альтернатива без SSMS (подставьте свой SQL-сервер и параметры TLS):

```powershell
$dbArgs = @{
    SqlServer = 'localhost\SQLEXPRESS'
    Database = 'IISReports'
    TrustServerCertificate = $false
}
& "$pkg\tools\Initialize-Database.ps1" @dbArgs
```

Этот инструмент применяет базовую схему 001, если требуется, затем 005, и запускает проверки. Он не пересоздаёт данные. `-CreateDatabase` для существующей базы не нужен.

## 4. Замените код, сохранив рабочую конфигурацию

После резервного копирования замените содержимое `App_Code` **целиком** файлами из `web\App_Code` нового пакета. Старых дополнительных/резервных `.cs` там быть не должно.

Обновите файлы:
- `web\Reports.ashx`;
- `web\index.html`;
- `web\v3.js`;
- `web\v3.css`;
- все `.cs` из `web\App_Code`;
- `build\IISReports.Agent.exe` → `$agentRoot\IISReports.Agent.exe`.

Не перезаписывайте `Web.config`, `sites.json`, рабочие GeoIP/ASN-файлы и `IISReports.Agent.exe.config` шаблонами. В частности, сохраните:
`ConnStr`, роли Windows, **реальный `IISReportsPublicOrigin`**, webhook, разрешённые хосты проверок.

Если публичный адрес не меняется, исправление Origin заново не требуется. Не меняйте внешний HTTPS-адрес на `localhost`.

Не копируйте `IISReports.WebCore.dll`/тестовые DLL в `web\Bin`: эти классы ASP.NET компилирует из `App_Code`.

## 5. Включите автоматическое обнаружение

При остановленной службе:

```powershell
& "$pkg\tools\Install-AutoDiscovery.ps1" -AgentDirectory $agentRoot
```

Скрипт не пересоздаёт службу. Он:
- создаёт/обновляет защищённую задачу `IISReports-DiscoverSites`;
- устанавливает publisher в `%ProgramData%\IISReports\Discovery`;
- создаёт первый снимок IIS;
- выдаёт службе чтение существующих локальных W3C-каталогов;
- сохраняет резервную копию конфигурации службы и добавляет настройки обнаружения.

Проверка:

```powershell
Get-ScheduledTask -TaskName 'IISReports-DiscoverSites'
Get-Content "$env:ProgramData\IISReports\Discovery\sites.json" -Raw -Encoding UTF8 |
    ConvertFrom-Json |
    Select-Object success, machineName, generatedUtc, error
```

Ожидается `success=True`. Каталог без логов может иметь `waiting_directory`; это не требует ручной регистрации.

## 6. Запустите сайт и проведите проверку доступа

```powershell
Start-WebAppPool -Name $poolName

# Используйте СВОЙ рабочий адрес, совпадающий с PublicOrigin.
$publicUrl = 'https://reports.example.test:8443/'
& "$pkg\tools\Test-Http.ps1" -ApplicationUrl $publicUrl
```

Неверный Origin, отсутствие/неверный токен и отсутствие cookie должны отклоняться. Тест дополнительно проверяет защиту `sources-save` без изменения выбранных источников. При отказе проверки не отключайте защиту.

## 7. Запустите агент

```powershell
Start-Service IISReportsAgentV3
Get-Service IISReportsAgentV3
```

Сделайте `Ctrl+F5` в браузере. На вкладке **«Источники»** должны появиться источники и флажки.

После первого успешного обнаружения проверьте:
1. Ранее отключённый источник остался отключённым.
2. Новые источники включены, но отсутствующие каталоги показаны как ожидающие.
3. Снятый флажок → «Сохранить выбор» → повторная загрузка/перезапуск не включают источник обратно.
4. Исторические записи не пропали.
5. Включение продолжает чтение с контрольной точки.

Новый сайт включается автоматически. Флажок управляет импортом, а не историческим фильтром и не самим Logging в IIS.

## Откат

Не удаляйте таблицы или историю для отката. Остановите службу и пул, отключите задачу обнаружения и восстановите резервные копии приложения/конфигов. В 3.0.x проверка ожидает схему 300, поэтому возврат одних старых файлов при схеме 310 недостаточен. Для полного отката восстановите согласованную резервную копию БД в отдельную базу и переключите оба подключения; учитывайте записи, поступившие после создания копии.

Не редактируйте `SchemaVersions` вручную, чтобы скрыть несовместимость.
