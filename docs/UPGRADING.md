# Обновление существующей установки до 3.1.1

[← README](../README.md) · [Установка с нуля](INSTALL.md)

**Не запускайте чистую установку с новыми случайными именами поверх работающего сайта.** Сначала определите, что уже установлено.

3.1.1 использует прежнюю схему **310**. Изменения установщика и новая проверка `csrf-check` не требуют удаления или пересоздания SQL.

## 1. Сохраните рабочую конфигурацию

Сделайте резервную копию SQL средствами SQL Server и закрытую резервную копию каталогов сайта/агента. В копиях есть строки подключения: храните вне wwwroot, доступ только администраторам/SYSTEM.

Не помещайте резервные `.cs` в App_Code. Не публикуйте `tools`, `agent`, `sql` или весь ZIP как сайт.

## 2. Определите реальные имена и пути

```powershell
& "$env:windir\System32\inetsrv\appcmd.exe" list site
& "$env:windir\System32\inetsrv\appcmd.exe" list app
Get-CimInstance Win32_Service -Filter "Name='IISReportsAgentV3'" |
    Select-Object Name, State, PathName, StartName
```

Папка IISReportsV3 может обслуживаться сайтом с другим именем. Не подменяйте её имя именем пула.

## 3. Подготовьте НОВЫЙ каталог дистрибутива

Распакуйте 3.1.1 в `C:\Deploy\IISReports-3.1.1`, не поверх 3.1.0.

```powershell
Set-Location 'C:\Deploy\IISReports-3.1.1'
.\tools\Verify-Package.ps1
.\tools\Build-And-Test.ps1
```

Пока сборка не прошла, рабочие файлы не заменяйте. Храните предыдущий EXE для отката.

## 4. Проверьте SQL

Для уже установленной схемы 310 достаточно проверки:

```powershell
.\tools\Initialize-Database.ps1 -SqlServer 'localhost' -Database 'IISReports' -VerifyOnly
```

Это пример локального SQL; укажите фактический экземпляр. Для тестового SQL с недоверенным сертификатом добавьте `-TrustServerCertificate` только осознанно.

Если установлена ещё схема 300, требуется штатная добавочная миграция `005-auto-sources.sql`. Выполняйте её после резервной копии через `Initialize-Database.ps1` без `-VerifyOnly`; `-CreateDatabase` для существующей базы не нужен. Старые dbo-таблицы не удаляются и не включаются автоматически в ir3-отчёты.

## 5. Замените код в согласованное окно

Остановите **точный пул приложения** и `IISReportsAgentV3`. Не используйте глобальный `iisreset`, не останавливайте другие сайты.

Публикация:
- замените `Reports.ashx`, `index.html`, `v3.js`, `v3.css`;
- замените каталог `App_Code` целиком кодом из `web/App_Code`, предварительно сохранив старый снаружи web-каталога;
- замените только `IISReports.Agent.exe` в фактическом каталоге службы;
- **сохраните** рабочие `Web.config`, `IISReports.Agent.exe.config`, `sites.json`, GeoIP/ASN CSV и папку logs.

Новый EXE берите из успешной сборки 3.1.1. Не копируйте тестовые DLL в Bin.

Этот выпуск не переписывает ваши `ConnStr`, роли Windows и `IISReportsPublicOrigin`. Настройки публичного URL не следует заменять шаблонными значениями.

## 6. Обновите задачу обнаружения

Служба должна оставаться остановленной:

```powershell
.\tools\Install-AutoDiscovery.ps1 -AgentDirectory 'C:\Services\IISReportsAgentV3'
```

Укажите фактический путь службы. Команда сверяет его с зарегистрированным EXE и не выполняет SQL.

## 7. Проверьте веб и запустите службу

Запустите прежний пул приложения. Выполните:

```powershell
.\tools\Test-Http.ps1 -ApplicationUrl 'https://reports.example.test:8443/'
```

Подставьте **ваш действительный адрес**, не пример. Все CSRF-тесты и положительный `csrf-check` должны пройти. Затем:

```powershell
Start-Service IISReportsAgentV3
Get-Service IISReportsAgentV3
```

В health проверьте версию 3.1.1, SQL, heartbeat, discovery и ошибки. Чекбоксы и контрольные точки хранятся в базе и сохраняются.

## Если установка ещё не завершена

Рабочего сайта/службы может пока не быть. Тогда настройте `.psd1` и следуйте [INSTALL.md](INSTALL.md) с нужного шага.

Шаг Config может принять совпадающие подготовленные файлы и достроить недостающий. Это не универсальный конвертер старых конфигов: при отличии ConnStr или Origin он остановится. Не удаляйте существующие файлы ради продолжения.

## Откат

Остановите свой пул/службу, верните сохранённые код и EXE прежней версии, оставив совместимые конфиги. SQL в 3.1.1 не меняется; восстановление базы не требуется только ради отката кода 3.1.x. Возврат к версии со схемой 300 требует отдельного плана совместимости, не удаления таблиц 310.
