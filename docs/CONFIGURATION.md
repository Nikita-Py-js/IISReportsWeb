# Настройки

[← README](../README.md)

В рабочем сайте редактируется **один `Web.config`**. Никакой пары configDirectory/agent-local.config.

| Ключ | Назначение |
|---|---|
| `ConnStr` | Подключение MSSQL. При Windows-аутентификации работает учётная запись пула |
| `LogRoots` | Базовые локальные папки журналов, разделённые `;` |
| `ImportBatchesPerRequest` | Максимум порций файлов за одно обновление, по умолчанию 12 |
| `ImportSecondsPerRequest` | Мягкий бюджет между порциями, по умолчанию 12 с |
| `EvaluateRules` | Оценивать SQL-правила после импорта; `true`/`false` |
| `IISReportsCheckHosts` | Разрешённые имена хостов ручных HTTP-проверок, разделённые `,`/`;` |
| `IISReportsCheckPorts` | Порты ручных проверок, по умолчанию `80,443` |
| `IISReportsAllowHttpChecks` | Разрешить HTTP-проверки без TLS; по умолчанию `false` |
| `IISReportsWebhookUrl` | Необязательный JSON-webhook. Никогда не выводите секретный URL в чат |
| `IISReportsWebhookHosts` | Разрешённый хост для webhook |
| `IISReportsWebhookPorts` | Разрешённый порт webhook, по умолчанию `443` |

Одна порция читает до 2 MiB исходных байтов, до лимита строк парсера. SQL, перечисление каталогов и завершение текущей транзакции могут занять дольше мягкого бюджета. Увеличение бюджета увеличивает длительность HTTP-запроса, не создаёт фоновую службу.

Пример дополнительных журналов:

```xml
<add key="LogRoots" value="C:\inetpub\logs\LogFiles;D:\IISLogs" />
```

Папки `W3SVC*` внутри корней обнаруживаются при следующем импорте. Журналирование в IIS должно быть включено отдельно. `LogRoots` не выдаёт NTFS-права само по себе.

## Названия сайтов

Setup один раз записывает имена сайтов IIS в `sites.json` в корне веб-приложения:

```json
{
  "1": "Основной сайт",
  "2": "API"
}
```

Новые ID, появившиеся после установки, показываются как W3SVCn. Для своего имени добавьте запись в JSON. Эта карта не является обязательным снимком: срока годности и связи с Планировщиком нет.

## Мониторинг и уведомления

Обычное обновление не выполняет сетевые проверки и не отправляет сообщения наружу. Оно может оценить правила на уже импортированных данных и записать инциденты/уведомления в SQL.

Во вкладках Проверки/Уведомления кнопка «Выполнить» запускает одну просроченную HTTP-проверку, оценку правил и одну готовую отправку webhook. После перезапуска IIS незавершённая отправка может повториться: у сообщения сохраняется `eventId`, получатель должен учитывать возможные повторы.

При закрытой вкладке ни интервалы правил, ни повторные отправки не исполняются. Настроенный IntervalSeconds — ограничение «не чаще», а не гарантия расписания.

## Безопасность

У Simple нет встроенной авторизации. Установщик создаёт локальную анонимную привязку. После публикации извне **каждый допущенный IIS пользователь** получает права чтения и изменения.

POST требует `X-IISReports-Request: 1`; CORS не включён. Заголовок не является секретом. Не включайте CORS для произвольных Origin. Ограничения доступа, HTTPS, Windows Authentication или внешний шлюз настраиваются отдельно администратором.

## API для ручной диагностики

GET: `overview`, `sources`, `logs`, `health`, `diag`, `runtime`, `whoami`.

POST: `refresh`, `sources-save`, `file-verify?fileId=...`, `monitor`, `rule-save`, `check-save`, `incident-action`, `notification-test`, `notification-retry`.

Все POST используют Content-Type application/json и `X-IISReports-Request: 1`. Кнопки интерфейса выставляют их автоматически. GET не запускает импорт.

`file-verify` сверяет контрольные суммы; длительная проверка большого файла может не уложиться в тайм-аут HTTP. Replay и автоматическая смена поколения в этом упрощённом интерфейсе намеренно отсутствуют: без нужного оригинала нельзя безопасно переимпортировать изменившуюся историю.
